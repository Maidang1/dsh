# 行为一致性验证与发布标准

## 1 什么叫核心正确

本项目不追求源码逐行一致，也不承诺覆盖上游所有行为。正确性的对象是公开声明支持的场景：在相同前置条件和输入下，关键状态转换、事件因果、数据结果、错误与资源清理满足固定上游版本的契约。

动画正确、最终文字相同或测试数量多，都不能单独证明运行语义正确。例如模型最终回复相同，但 user/message 提交时机错误，仍属于核心问题。

## 2 行为契约模板

每个契约保存以下字段：

```text
ID 与名称
上游 commit、文件、符号、相关测试
适用范围与不支持范围
输入和前置状态
触发操作
允许的状态转换与守卫
关键事件顺序或偏序约束
数据输出与 Session 变化
失败、取消、清理行为
教学实现位置
规范化规则
验证方式与结果
```

验证等级：draft 表示尚未通过；contract-verified 表示已通过有源码依据的契约测试；upstream-compared 表示额外通过同场景上游参考实现的差分测试。任何等级都必须附带覆盖范围，不代表全插件所有分支一致。

## 4 测试分层

### 4.0 第一条契约的可执行规格

PROMPT-01 与 PROMPT-04 可以先按下面的规格落地。名称和测试数据属于本项目，行为依据为上游 section 注册与组装机制。

前置条件：根作用域存在提示词服务；固定初始片段为“你是一个助手”；贡献插件声明 section 名称 lesson:style、有限 order 和文本“回答时使用短句”；模型适配器记录实际收到的请求。

| 操作 | 期望证据 |
|---|---|
| 不挂载贡献插件，运行输入“你好” | 请求不含新增文本，保存基线请求 A |
| 挂载贡献插件 | 出现一条属于该实例的注册项；此时没有凭空产生模型请求 |
| 运行相同输入 | 新请求 B 包含该片段，片段出现次数与排序符合契约 |
| 比较 A、B | 除允许的运行标识等非语义差异外，变化可归因于新增片段 |
| 保存 B 快照后卸载插件 | 注册项被释放；已经记录的 B 不被修改 |
| 再次运行相同输入 | 新请求 C 不包含片段，规范化提示词恢复至 A |
| 再次挂载并运行 | 注册没有泄漏，片段只出现一次 |

额外失败输入：同域重复名称、非有限 order、缺少依赖服务。测试应断言错误发生的阶段及没有产生的副作用，而不是仅断言抛出了某个异常。

如果教学版本无法保留以上任一行为，不能将该阶段标为该契约已通过。

### 4.1 纯领域与投影测试

覆盖服务解析、注册释放、事件分发、数据投影、轨迹规范化和对比算法。构造行为输入，而不是只检查内部函数是否被调用。

关键属性测试：同一序列前向回放与检查点恢复结果相同；seq 重复消息不会重复应用；同作用域实例 ID 唯一；卸载后资源数恢复；固定种子执行的规范化结果稳定。

### 4.2 阶段构建测试

遍历所有 executable 阶段，执行类型检查、打包、场景与断言。验证每个展示片段都来自相同源码文件，所有 SourceRef、架构节点和 contractId 可解析。

禁止跳过早期阶段，只测试最终阶段。早期可编译但行为不符合阶段说明，同样应失败。

### 4.3 Node 运行宿主集成测试

覆盖本地 API/SSE 与子进程 IPC 的消息验证、批量记录、重复消息、晚到消息、序号缺口、错误、取消、强制终止和大小限制。验证浏览器重连不触发重复执行，旧 generation 数据不污染新运行，环境快照和日志不泄露密钥。检测观察器关闭与开启时的语义结果是否一致。

真实模型与真实文件边界另做 Node 集成验证，记录适配器、环境和实际输出。严格契约回归继续使用确定性适配器；真实外部服务返回不同内容时，不以输出逐字一致作为通过标准。

### 4.4 浏览器端到端测试

至少实现以下场景：

1. 首屏启动最小组合并查看请求。
2. 添加提示词插件，重新运行并查看真实差异。
3. 进入插件，切换 Code Hike 阶段，确认执行的是选中阶段。
4. 点击轨迹定位正确实例、正确版本的代码。
5. 移除插件，注册消失且后续请求恢复。
6. 添加工具，执行调用并观察结果进入后续请求。
7. 进入缺失依赖、错误和取消场景，查看可解释状态。
8. 保存/刷新/导入后回放一致。
9. 运行中修改草稿，旧运行不被污染。
10. 通过键盘完成最小闭环，减少动画模式仍可辨认差异。

视觉快照只覆盖稳定布局和重点状态，不对每一帧动画做易碎截图测试。

## 5 上游差分测试

### 5.1 参考执行器

在 Node 测试环境中固定上游 commit，使用其实际服务或测试夹具执行相同的限定场景。完整应用启动如有必要走上游支持的 profile 入口；测试级直接挂载只用于对照测试，不伪装成新的上游应用启动方式。

以确定性模型和内存适配器消除网络波动。适配器只替换外部边界，不在适配器里模拟待验证的提示词组装、工具执行或 Session 逻辑。

### 5.2 对照投影

教学与上游实现不必产生完全相同的日志。二者映射到同一份契约级输出，例如：

```ts
interface ContractObservation {
  registrations: unknown[]
  requests: unknown[]
  durableEvents: unknown[]
  lifecycleTransitions: unknown[]
  dispatchSpans: unknown[]
  remainingResources: unknown[]
}
```

unknown 在实际实现中替换成具体 schema；这里仅表达对照维度。

允许规范化随机 ID、绝对路径、墙钟时间与独立流式 chunk 的分割。必须保留调用对应关系、角色、文本、工具参数、结果、关键顺序与因果。

不要通过任意排序消除顺序错误。并发分支按源码契约比较偏序；有序串行链比较严格顺序。忽略字段名单必须显式维护并有理由。

### 5.3 失败处理

差分失败时输出首个差异、两侧源码版本、输入、规范化结果和相关 span。先判断契约理解错误、教学实现错误或参考夹具错误，再修改相应部分。

上游基线不自动跟随 master。升级通过单独任务审查差异、重新生成参考输出、更新课程，并保留旧版本轨迹的只读回放。

## 6 CI 与本地命令规划

以下命令是未来 package.json 的目标脚本，本次文档提交尚未实现：

```sh
pnpm typecheck
pnpm lint
pnpm lessons:build
pnpm lessons:verify
pnpm test:contracts
pnpm test:trace
pnpm test:upstream
pnpm test:e2e
pnpm build
```

PR 必跑类型、契约、内容和受影响闭环。上游对照可缓存固定依赖，但不能跳过受改动影响的契约。完整浏览器与性能回归在发布候选执行；发现相关失败后再扩大测试。

不需要为纯文案或布局细节新增镜像实现的单元测试。优先验证可能导致错误教学的语义与版本关联。

## 7 内容真实性检查

- 上游链接包含完整 commit，不指向会变化的 master 作为实现依据。
- 源码路径存在，提取范围及哈希对应。
- 教学代码明确标注为精简实现，不能与上游原文混排而不标识。
- 课程中的事件名来自实际支持列表；教学检查点使用独立命名空间。
- 架构连线有代码或观测依据，解释性连线有标识。
- 说明“会执行”时，存在场景证据；否则改为“注册后可被调用”。
- 每个阶段都有删减说明，未覆盖能力不能被配置启用。
- Code Hike 动画与实际模块源码哈希一致。

## 8 发布门槛

发布前必须满足：

- P4 样板闭环完整，P5 首批核心插件可用。
- 所有阻断契约通过，没有未解释的差分失败。
- 展示与执行的代码版本一致。
- 回放、历史运行和当前草稿不混淆。
- 本地 Node 命令可启动；默认模式无 API Key 可用，真实/确定性适配器与环境来源标识明确。
- Node 实际执行数据完整驱动现有可视化，刷新可重连，传输与导出不含密钥。
- 异常、取消、依赖缺失、清理和容量失败有明确 UI。
- 性能、键盘和减少动画检查完成。
- 上游 MIT 及实际引入依赖的许可证归属被保留；复制或改写的源码保留需要的声明。
- 安装、开发、构建、内容制作和支持范围文档与实际功能相符。

## 9 已知风险与处理

| 风险 | 后果 | 处理 |
|---|---|---|
| 重写 Cordis 语义不准确 | 教错依赖、作用域和事件 | 优先复用；无法复用则先契约和差分 |
| 阶段源码与展示双维护 | 看到的代码不是执行代码 | 单一源码与哈希校验 |
| 把复杂分支一律删掉 | 正常场景外流转错误 | 显式支持范围，未知配置拒绝，覆盖错误与取消 |
| 依赖上游快速更新 | 内容链接和测试漂移 | 锁 commit，人工升级基线 |
| 把单步动画当调试 | 误导因果和时序 | 回放与执行暂停分开 |
| 内容制作成本高 | 图谱大但单插件内容空 | 先一条纵向样板，再复制模板 |
| 工具运行造成外部影响 | 教学实验不可重复 | 第一版内存工具和受信任阶段模块 |
| 过量轨迹拖慢 UI | 学习过程中卡顿 | 批传、虚拟列表、快照、明确采集上限 |
