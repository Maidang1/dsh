# 分阶段实施计划与任务验收

## 1 实施策略

先构建一个从源码到执行到可视化的纵向闭环，再横向增加插件。不要先完成一个漂亮的全仓库图谱，再补真实运行。

下面所有任务均为待实施。任务编号用于本地文档追踪，不代表已经创建远端 issue。预估以一名熟悉 TypeScript/React 的开发者计算，包含基本测试与文档；兼容性和上游差分适配会影响工期，阶段 0 后重新估算。

| 阶段 | 主要交付 | 依赖 | 初步工作量 |
|---|---|---|---|
| P0 | 基线、语义契约、Code Hike/Worker 技术验证 | 无 | 3–5 人日 |
| P1 | 工程骨架、类型、内容构建骨架 | P0 | 2–3 人日 |
| P2 | 无 UI 的最小运行时、记录和回放 | P1 | 5–8 人日 |
| P3 | 插件树、轨迹和数据对比实验台 | P2 | 4–6 人日 |
| P4 | 一个插件的 Code Hike 完整学习闭环 | P2、P3 | 4–6 人日 |
| P5 | 工具、中间件、作用域与异常教学覆盖 | P4 | 5–8 人日 |
| P6 | 可选协作式执行单步 | P5 | 2–4 人日 |
| P7 | 性能、持久化、可访问性和发布验收 | P5；若含 P6 则依赖 P6 | 3–5 人日 |

第一条可演示闭环是 P4 完成；第一版发布需要 P5 和 P7。P6 不是发布前置条件，回放单步已经属于 P3。总工期不是承诺，不能将工作量直接视为日历排期。

## 2 P0 固定依据和验证风险

### P0-01 固定上游基线

输入：当前参考 commit `687f282e8625c6b8d11ff58211a90524be2e4317`。

工作：保存 upstream-lock.json，包括仓库、commit、读取日期、相关包版本和许可证；定位 Cordis、session、system-prompt、tools、agent-loop、llm 的实现及测试。读取实际最小配置，列出最小框架树与最小对话树的差异。

交付：基线清单、实际文件与符号索引、依赖闭包说明。

验收：每个核心能力能跳转到固定 commit 的实际文件；最小组合清单标明已证实和待验证项。不得将 sdk-minimal profile 等同于最少节点的教学组合。

### P0-02 建立第一批行为契约

工作：明确依赖激活、作用域解析、注册释放、waterfall、Session 提交和请求准备等行为。每个契约包含正常、失败和清理用例；写明覆盖范围。

交付：docs/contracts 下的契约与测试用例设计。

验收：核心规则有源码/测试依据，尚未支持的分支有明确状态，没有自造的上游状态名称。

### P0-03 Code Hike 与 Worker 技术验证

工作：构建一个两阶段 TypeScript 示例，使用同一份代码生成动态展示和 Worker 模块。验证 Next.js 静态导出、代码过渡、模块哈希、Worker 构建及部署路径。

交付：最小验证页面、兼容版本表、技术决策记录。

验收：第二阶段代码变化确实改变 Worker 结果；关闭动画仍可读；静态构建产物能运行；不使用 eval。

### P0-04 Cordis 复用决策

工作：核查固定版本包是否能在浏览器 Worker 中独立构建；用一个服务、一个消费者和一个 disposer 验证挂载/等待/卸载。

交付：复用或精简重实现的决定、包体积和不支持项、基础契约执行方式。

验收：决定有实际构建与行为结果支持。若重实现，必须明确其教学子集和上游对照入口，不能只凭“API 看起来简单”决定。

### P0 退出条件

版本与选型已锁定，最小树有依据，至少一个可执行增量演示通过，关键语义契约无阻塞未知项。否则继续 P0，不开始批量内容制作。

## 3 P1 工程与内容基础设施

### P1-01 初始化 workspace

建立 apps/explorer、contracts、teaching-runtime、teaching-plugins、trace、lesson-kit。配置 TypeScript strict、格式检查、Vitest、Playwright 和 CI。只安装实际需要的依赖。

验收：干净环境 install、typecheck、build、基础测试通过；包依赖方向无循环；README 提供可验证启动说明。

### P1-02 建立公共协议

实现 ExperimentRevision、PluginInstance、SourceRef、TraceRecord、RunManifest、Worker envelope 和 Zod schema。

验收：非法版本、缺失 ID、错误 payload 被拒绝；导入数据不触发代码执行；类型与运行时 schema 一致。

### P1-03 建立内容编译器骨架

扫描 manifest，类型检查完整阶段，生成 sourceHash、可执行模块列表和源码锚点。先实现一个插件的两个阶段。

验收：不存在的锚点、重复阶段 ID、无法编译的 executable 阶段使构建失败；展示与执行 hash 相同。

## 4 P2 最小教学运行时和轨迹

### P2-01 Context、依赖和作用域

按 P0 决策接入或实现基础机制。实例拥有独立 ID 和资源集合，解析服务时记录 scope 与 provider。

验收：消费者先于提供者挂载时不提前执行；补齐后按契约激活；两个作用域互不污染；依赖错误能定位。

### P2-02 注册与生命周期

实现工具/提示词/监听器注册所需的资源机制，支持可逆注册和可观察的卸载。

验收：重复注册规则正确；卸载无残留注册；重复释放处理符合契约；清理失败不被报告为成功。

### P2-03 事件分发

实现第一批需要的分发模式与 waterfall。记录进入、委托、短路、返回和异常。

验收：A-before、B-before、B-after、A-after 顺序正确；短路不调用下游；返回值和异常传播正确。未覆盖模式显式拒绝。

### P2-04 最小对话运行

实现 Session、提示词组装、模型服务和 Agent Loop 的受支持子集。模型采用确定性脚本，保持响应由实际请求驱动。

验收：固定输入生成请求、流式响应和正确结算；拒绝输入不伪造 step；请求准备取消不提前提交用户/system；错误状态可解释。

### P2-05 Recorder、Reducer 和 Worker

记录不可变数据、SourceRef、因果 span 和 seq。构建纯回放 reducer、初始快照、事件批传与 run settlement。

验收：同一场景重复运行规范化结果相同；从头回放与快照跳转结果相同；旧 Worker 消息不会污染新运行；finalSeq 缺失时不显示完整。

### P2 退出条件

命令行/测试环境中能运行最小组合，添加提示词贡献产生真实差异，卸载恢复，保存轨迹可离线回放。此时可以没有精美 UI。

## 5 P3 整体实验台

### P3-01 插件树与选择

实现稳定布局、自定义节点、作用域容器、折叠、实例选择和节点状态。树边与依赖边分层。

验收：多实例不合并，状态只来自运行投影；缺失服务和 disabled 可区分；运行事件不使布局抖动。

### P3-02 添加插件与实验版本

实现插件库、配置校验、依赖预览、草稿、不可变 revision 和运行绑定。

验收：新增插件创建新 revision；历史运行绑定旧组合；运行中改草稿不修改正在执行的模块。

### P3-03 时间线与回放

实现按事件/检查点切换游标、倍速播放、暂停回放、状态和数据联动、错误定位。

验收：每次单步来自实际记录；返回过去位置不执行新工具；临时事件与 Session 事件有类型标识。

### P3-04 前后运行对比

实现请求、注册项、轨迹和会话数据 diff；检查场景/输入等可比条件。

验收：相同条件下清楚展示一个插件带来的差异；不同输入时显示对照条件不同；大 JSON 可按字段展开。

## 6 P4 单插件代码学习闭环

### P4-01 Code Hike 教学面板

集成插件阶段导航、多文件展示、增量、焦点、源码提及和减少动画。使用 lesson-kit 构建产物。

验收：阶段切换不修改回放游标，运行按钮绑定当前阶段 sourceHash；动画关闭也能识别变化。

### P4-02 插件内部架构

建立架构节点/边、源码定位、职责解释和运行检查点联动。先覆盖提示词贡献插件。

验收：每个架构节点有实际依据或明确标注解释；选中代码可定位架构；选中轨迹可定位代码和实例。

### P4-03 完成提示词插件样板

实现入口、依赖、注册、清理与局部覆盖相关阶段，加入最小场景和上游映射。测试重复名称、顺序和卸载。

验收：用户无需 API Key，能从最小树完成添加、代码学习、运行对比和移除。结果不由课程 JSON 伪造。

### P4-04 形成作者模板

交付可复制的插件 lesson 目录模板、契约模板、架构 schema 和内容检查命令。

验收：新增第二个插件不需要改运行器或 UI 的核心分支，只需补充实际需要的能力和内容。

## 7 P5 扩展核心机制

### P5-01 工具调用闭环

实现一个内存工具的 schema、注册、参数校验、执行、工具结果和下一次请求；脚本模型必须依据实际工具声明作出响应。

验收：正常调用、未知工具、参数错误、执行失败均有独立轨迹；错误分支顺序与契约一致。

### P5-02 中间件与拦截

实现两层监听器和委托/短路阶段，展示 around 调用栈与返回过程。

验收：实际执行和 Code Hike 阶段对应，短路后的节点显示未触发而不是失败。

### P5-03 作用域与生命周期实验

两个作用域挂载同类插件，观察局部覆盖、资源所有权和卸载。

验收：改变一个实例不影响另一个；依赖丢失与恢复符合上游契约；卸载清理有证据。

### P5-04 上游行为对照

为第一批核心能力建立 Node 参考运行脚本或上游测试包装，生成规范化结果。运行教学版与参考版对照。

验收：关键 release-blocking 契约有源码依据和可重复测试；无法对照的项目显示 contract-verified，不标 upstream-compared。

## 8 P6 可选协作式执行单步

实现语义检查点暂停、继续、继续至下一检查点与取消。记录暂停位置及仍在执行的异步任务。

验收：开启/关闭暂停控制的规范化结果一致；暂停时可取消；不会声称是上游原生逐行调试；真实外部效果不可回退。

若该阶段延迟，第一版保留完整回放单步，UI 不显示不可用的执行暂停按钮。

## 9 P7 发布前收口

### P7-01 本地保存与导出

持久化 revision、manifest、trace chunks、payload 和学习进度，提供导出、导入、容量管理。

验收：刷新可恢复记录；schema 不兼容可解释；配额失败不丢当前内存结果；导入不会执行代码。

### P7-02 性能与可访问性

测量标准场景，处理代码高亮、布局和长轨迹瓶颈；补齐键盘、焦点、文本替代和减少动画。

验收：达到技术架构中的性能目标或记录明确修正；关键闭环可键盘操作；移动/窄屏不挤压代码。

### P7-03 文档与来源说明

更新运行说明、插件覆盖表、上游版本、教学精简边界、许可证归属和故障处理。

验收：没有把教学实现称作完整 Harness；没有虚构上游文件路径；每个插件显示验证等级。

### P7-04 构建与发布验收

构建静态产物并执行 Playwright 核心流程，检查子路径部署、Worker URL 和离线内容资源。生产发布按实际用户部署指令执行，不因本计划自动发布。

验收：无凭证也能完整体验第一版；构建、行为、内容和端到端检查全部通过。

## 10 首次开发的具体顺序

1. 完成 P0-01 和 P0-02，写出真正的最小组合及第一条提示词契约。
2. 完成 P0-03，证明动态代码和执行模块可共用源码。
3. 完成 P0-04，固定 Cordis 基础机制实现方式。
4. 完成 P1 的工程、类型与构建工具。
5. 实现 P2，先让测试证明“添加提示词插件会改变请求”。
6. 实现 P3，显示真实树、轨迹与 diff。
7. 实现 P4，把同一个插件变成完整学习样板。
8. 评审用户是否真正看懂插件后，再进行 P5 的内容扩展。

## 11 每个任务的完成记录

任务完成时记录修改文件、通过的验收项、测试命令、未支持的边界、关联契约和源码版本。不能以“组件已写完”代替功能闭环验收。

遇到上游语义与方案不一致时，先修正契约和文档，再修改教学实现与内容，最后重新生成轨迹。不要调整预期结果来掩盖行为差异。
