# 从架构读懂 DeepSeek Harness（系列文章）

这组文章从架构出发介绍 DeepSeek Harness（`dsh`）：它为什么把一切都做成插件，插件靠什么组合在一起，一次对话在内核里怎样流动，以及这种设计换来了什么、付出了什么。

读者对象：想读 dsh 源码、给 dsh 写插件，或者在设计自己的 agent harness、想参考 dsh 做法的工程师。默认读者熟悉 TypeScript 和 LLM 工具调用的基本概念，不要求事先了解 Cordis。

## 版本基线

所有文章以 **dsh-v0.2.1-rc.2**（上游 commit [`687f282e`](https://github.com/deepseek-ai/deepseek-harness/tree/687f282e8625c6b8d11ff58211a90524be2e4317)，2026-10-17）为准，也就是 npm 上 `@deepseek-ai/dsh-*@0.2.1-rc.2` 对应的源码，与本仓库 [upstream-lock.json](../../upstream-lock.json) 锁定的版本一致。文中的源码链接都是指向该 commit 的永久链接，代码片段从该 commit 摘录；标注“节选”的片段删掉了与论点无关的行，没有改写保留下来的代码。

dsh 仍处于 developer preview，上游明确声明会有破坏兼容性的变更。阅读更新版本时，事件名、字段名和包名都可能已经变化，请以对应版本的 `docs/architecture.md` 为准。

## 写作约定

这组文章按对外发布的技术博客标准编写，后续补充或修订时请沿用。中文排版与行文遵循阮一峰《[中文技术文档的写作规范](https://github.com/ruanyf/document-style-guide)》：中英文之间加空格，引号用“”，标题不跳级、不出现孤立子标题，句子不超过 40 字，段落不超过七行，避免感叹号。此外：

- **每篇有元信息。** 开头的 front matter 写明标题、摘要（40 到 160 字）、日期、作者、标签、系列序号与版本基线；正文开头用引用块说明本文回答什么问题，结尾有“小结”和“参考”。
- **事实可追溯。** 涉及 API、事件、字段、默认值的陈述都能在基线 commit 的源码或文档中找到依据，并给出永久链接。无法核实的内容不写；推断要明确标成推断。
- **代码来自源码。** 片段从基线 commit 摘录，不凭记忆改写。示意性的伪代码要标明“示意”。
- **一篇一个主题。** 每篇控制在 15 分钟左右的阅读量；跨篇引用用相对链接，不重复展开。
- **说清取舍。** 架构文章不只讲优点，每篇都交代这种设计的代价或限制。
- **图用 Mermaid 或纯文本。** 保证在 GitHub 上直接渲染，不依赖外部图床。
- **术语前后一致。** 首次出现时给出中英文对照（如“轮次（turn）”“步骤（step）”），之后统一用同一个词。

## 与 Harness Explorer 的关系

本仓库是 Harness Explorer，一个直接运行上游发布内核包的交互式学习实验台。文章里讲到的部分机制（提示词片段的作用域、`tools/pre-execute` 的洋葱顺序、system-prompt 的组装）在 Explorer 中有可运行的课程，文中会在相应位置指出。想边读边看真实执行轨迹，可以按[根目录 README](../../README.md) 启动 Explorer。
