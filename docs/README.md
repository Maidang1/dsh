# Harness Explorer 实现文档

本方案将产品交互、精简运行时、源码教学内容和行为验证拆成可独立交付的阶段。执行顺序是先证明核心机制正确，再接入可视化和 Code Hike，最后扩展插件覆盖。

文档日期：2026-10-18。最新设计：本地 Node 启动，保留原有数据流与可视化，以实际执行数据驱动展示；持久化、运行隔离、混合组合与场景模型已按 Node 架构统一。状态：第一版已实现。阶段 0 的复用决定见 [decisions/0001](decisions/0001-upstream-baseline-and-reuse.md)，内核改为直接运行上游发布包见 [decisions/0002](decisions/0002-run-upstream-packages.md)，契约及其测试见 [contracts](contracts/README.md)，新课程的制作流程见 [authoring](authoring.md)；依赖版本由 `pnpm-lock.yaml` 锁定。

## 已确定的产品约束

- 服务首次理解 DeepSeek Harness 原理与源码设计的人。
- 从最小插件树出发，在同一棵树上逐个添加插件，观察数据流变化。
- 以状态及状态转换作为解释依据，不能用预设动画冒充运行结果。
- 每个插件都能展开内部代码架构、服务依赖、事件关系、生命周期和关键源码。
- 使用 Code Hike 动态展示代码增量，增量应能对应到可执行阶段。
- 允许精简、重写上游代码，保证已覆盖场景的状态与流转语义正确。
- 简化模型调用、文件系统等外部设施时，明确区分确定性适配器和真实外部服务。

## 关键技术决策

| 决策 | 本版方案 |
|---|---|
| 执行模型 | 混合组合：对话内核直接执行 npm 发布的 `@deepseek-ai/dsh-*@0.2.1-rc.2`（固定 commit 的发布，decisions/0002）并通过观测适配记录；被讲解的插件使用分阶段教学实现 |
| 前端 | Next.js（静态导出）、React、TypeScript、MDX、Code Hike；版本与托管方式在阶段 0 验证后锁定 |
| 图展示 | React Flow；初始树形布局保持稳定，复杂关系按需使用 ELK |
| 状态管理 | Node 端 XState 只控制一次运行的校验、启动、停止与结算，同一时间只运行一次；每个实例独立记录运行状态；草稿与版本由 Node 实验仓库管理；Zustand 保存视图选择与回放游标 |
| 执行位置 | 本地 Node 控制服务为每次运行新建子进程，执行受信任的预构建插件阶段模块 |
| 外部能力 | Node 可读取实际环境并接入真实模型和文件；确定性模型与内存适配器保留用于教学、严格对比和测试 |
| 存储 | Node 本地运行仓库 `.explorer/` 保存草稿、版本、运行记录与学习进度；浏览器只存 UI 偏好 |
| 场景 | 场景是有序步骤（输入、挂载、卸载、快照、取消），确定性模型脚本按实际请求匹配响应 |
| 单步 | 默认回放真实教学执行轨迹；协作式执行暂停在后续阶段实现 |
| 教学内容 | 完整阶段源码是唯一来源，派生展示片段、执行模块、架构关联和内容哈希 |
| 验证 | 契约测试、关键上游差分测试、内容编译验证和端到端学习闭环 |
| 交付 | 本地 Node 应用，单进程单端口同源托管前端与 API，回环绑定并使用会话令牌；应用尚未实现 |

## 术语

| 术语 | 定义 |
|---|---|
| 插件定义 | 可以被挂载的代码及其配置约束 |
| 插件实例 | 在特定作用域中挂载的一次插件，具有唯一实例 ID |
| 插件树 | 实例的组合与父子层级，不代表执行顺序或所有服务依赖 |
| 服务依赖图 | 实例提供、需要和解析服务的关系 |
| 架构图 | 插件内部的文件、符号、职责与协作关系 |
| 教学阶段 | 一份完整可编译源码、解释和运行场景的组合 |
| 实验版本 | 插件组合、配置、阶段版本和场景的不可变组合，由 Node 实验仓库生成 |
| 可执行阶段 | 一份可运行模块及其 sourceHash、所需与提供的服务；组合只能引用可执行阶段 |
| 场景 | 一次运行中依次执行的输入与生命周期步骤，属于实验版本 |
| 模型脚本 | 确定性模型适配器按实际请求匹配的响应规则，不是预录轨迹 |
| 适配器模式 | deterministic 使用模型脚本与内存适配器；real 使用本机凭据接入真实模型 |
| 运行 | 在某个实验版本上执行一次场景；具有唯一 runId |
| 轨迹 | 一次运行实际产生的观察记录，不等同于 Session 日志 |
| 回放游标 | 当前查看到轨迹中的哪个位置，不改变实际执行状态 |
| 行为契约 | 保留的状态、条件、顺序、数据与清理规则，以及验证用例 |
| 语义检查点 | 教学实现中可观察的执行边界，不声称是上游已有的调试 API |
| 控制服务 | 本地 Node 进程，托管前端、提供 API、管理实验仓库与运行子进程 |
| 运行子进程 | 每次运行新建、运行结算后退出的执行进程 |
| 观测适配 | 在 Cordis 边界只读记录上游复用插件行为的适配层 |
| 环境快照 | 本次运行所用环境信息的脱敏记录，不含变量值和绝对路径 |
| 运行仓库 | 控制服务维护的本地文件存储 `.explorer/` |

## 完成标准

用户可以从最小组合开始，运行固定输入，添加一个插件，进入插件内部，通过动态代码步骤构建功能，再次运行同一输入，看到由实际执行产生的状态和数据差异，并打开对应的上游依据。任何“已验证一致”的声明都能追溯到具体契约和测试报告。
